# デスクトップ自動掃除プログラム (Desktop_Cleaner)

##  概要
デスクトップ上のショートカットファイル等を除くすべてのファイルを、自動的に指定されたファイルサーバー（またはローカルの所定フォルダ）へ移動・退避させるPythonスクリプトおよび運用パッケージです。

##  開発の背景 / 目的
* 課題: 現場のフロントPC（受付・店舗端末など）のデスクトップ上に、一時的に作成・ダウンロードされた顧客情報や機密データがそのまま残置されているケースが多く、不特定多数の目に触れることによる情報漏洩のリスクや物理的なセキュリティ上の懸念が生じていた。
* 解決: 本プログラムをタスクスケジューラにより自動で定期実行することで、各現場の繁忙度に関わらず強制的なデータクレンジングを実現。重要なファイルは即座にセキュアな中央ファイルサーバーへ集約され、現場の端末にデータを残さない強固なセキュリティ体制を確保した。

## 主な機能
* デスクトップ内のアイテムを自動判別し、ショートカットファイル（.lnk）やシステムファイル（.ini）、Pythonスクリプト（.py）などを除外した全ファイルを退避対象とする。
* 退避先として社内の共有ファイルサーバー（UNCパス等）を指定可能。
* 移動先に同名のファイルが既に存在する場合などの競合時にも、プログラムが異常終了（クラッシュ）しないよう安全にスキップして処理を継続する。

## 使用技術・動作環境
* 開発言語: Python 3.14
* 主要ライブラリ: pathlib, shutil, python-dotenv, PyInstaller
* 対象OS: Windows 10 / 11

## 使い方・社内展開方法
本プログラムは、Python環境がインストールされていない一般的な実務PCでも動作するよう、exeファイル化およびバッチファイル（.bat）による自動導入パッケージとして構成されています。リモートデスクトップ等での個別設定は不要です。

1. 共有フォルダへの配置
社内の共有ファイルサーバー（例: \Server\Share\Desktop_Cleaner）を作成し、以下のファイルを配置します。
* main.exe （PyInstallerでビルドしたスタンドアロン実行ファイル）
* .env.example （環境変数の設定雛形）
* install.bat （インストーラー兼タスクスケジューラ自動登録バッチ）

2. 各PCでのインストール（ワンクリック導入）
 1. 展開したいクライアントPCから上記共有フォルダにアクセスし、install.bat をダブルクリックします。実行により以下の処理が全自動で行われます。
 2. 各PCのローカル（C:\Users\ユーザー名\Documents\Desktop_Cleaner）に専用フォルダが作成される。
 3. 共有フォルダから、main.exe および設定ファイル（.env）がローカルへ自動的にコピーされる。
 4. Windowsのタスクスケジューラへ、本プログラムを定期実行（例: 毎日17:00の退勤時）するためのタスクが自動登録される。

3. 各PCでの初期設定
 1. 導入処理完了後、自動的にローカルのフォルダが開きます。
 2. フォルダ内の .env ファイルをメモ帳等で開きます。

以下の項目を、そのPCの環境および社内のルールに合わせて書き換えて保存します。

（設定ファイルの中身の例）
DESKTOP_DIR=C:\Users\実際のユーザー名\OneDrive - 会社名\デスクトップ
TARGET_DIR=\192.168.1.100\Security_Backup\Desktop_Clean
EXCLUDE_EXTS=.lnk,.py,.ini

※ main.exe のショートカットをデスクトップ等に作成しておくことで、スケジュール時間外でも手動による即時お掃除が可能です。

## 工夫した点・エンジニアリング視点でのアピール
* ファイルサーバー連携による強固なデータ保護（エンドポイントセキュリティ）
退避先（TARGET_DIR）を各PCのローカルではなく、社内の中央ファイルサーバーのネットワークパスに指定可能に設計。これにより、紛失・物理的盗難リスクのある現場端末から速やかに機密データを排除するとともに、サーバー側での強固なアクセス権限管理（一般スタッフの閲覧制限など）や一元バックアップの運用を可能にし、実務に耐えうるセキュリティ体制を構築しました。

* 情報漏洩の防止（環境変数による設定管理）
ソースコード内に本名や社内ファイルサーバーのIPアドレス、機密フォルダパスを直書きせず、.env ファイル（環境変数）を介して動的に読み込む設計を採用。これにより、プログラムをGitHub等の公開リポジトリで管理・ポートフォリオ公開する際の情報漏洩リスクを完全に排除しつつ、PCごとの個別環境設定にも柔軟に対応できるポータビリティを確保しました。

* 非エンジニアへの配慮（ノーコード・ゼロタッチ展開）
現場スタッフのITリテラシーに関わらず一斉展開できるよう、環境依存を排除したシングルexe化を採用。さらに、タスクスケジューラへの登録コマンドを含む導入工程をバッチファイルで自動化したことで、管理者が1台ずつリモートデスクトップで設定する手間をなくし、運用のスケール（他拠点への一斉配布など）を見据えた設計を行いました。

* 堅牢なエラーハンドリング
ファイル移動時に「既に同名ファイルがファイルサーバー側に存在する」などの競合エラーが発生した場合でも、システム全体をクラッシュ（異常終了）させず、try-except 構文によって該当ファイルのみを安全にスキップして残りの処理を完遂させる、現場運用を止めない耐久性を持たせています。
